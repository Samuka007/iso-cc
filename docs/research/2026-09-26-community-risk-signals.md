# 社区风控信号面（Q3）：claude 封号信号、社区检测工具与 T5/R12 增补建议

日期：2026-09-26 ｜ 状态：研究笔记（info-only，不改需求基线 `docs/REQUIREMENTS.md`）

## TL;DR

1. **唯一被官方行为直接证实的信号是"出口 IP 归属地 ∈ 支持地区"**：非支持地区直连得到确定性的 `400 Access to Anthropic models is not allowed from unsupported countries…`（GH anthropics/claude-code#2656 [一手]）。这是唯一有官方语义、环境工具完全可测、适合做**硬断言**的风控面。社区同时报告：**区域阻断 ≠ 封号**——中国 IP 只报不支持，真正封号另有逻辑（linux.do/t/2804986 [社区-孤例]）。
2. **社区共识面很宽，但绝大多数在 iso-cc 出界处**：机房 IP 类型/欺诈分、支付卡头连坐、用量节奏、账号年龄、邮箱来源、KYC（Persona）。其中只有 **IP 类型 + DNS/WebRTC 泄漏 + 时区-geo 一致性**属于环境可测面，且这三块 P1–P12/R12 已经覆盖。
3. **最重要的社区反证：环境全对照样封**——硅谷稳定出口 20 天被封（V2EX t/1223262）、法国家宽 VPN 全员同日封（t/1148482）、"英国漫游流量+已 KYC+英国时区+关定位"5 小时封（linux.do/t/2952716）、同指纹同环境一批号有封有不封（t/2837401 楼 8、t/2804986 楼 8）。⇒ **环境一致性是必要非充分**；`iso-cc verify` 的裁决语义必须钉死为"**会话环境与声明一致**"，绝不能暗示"账号不会封"。
4. **行为/内容/账号层是社区公认更强的信号，结构性超出环境工具能力**：用量画像与 24h 在线、对话内容/蒸馏扫描、被封项目特征关联（"开老项目 1 小时内被封"）、OAuth Token 异地漂移。verify 应输出**明确的"本工具不覆盖面"声明**，而不是假装探针矩阵穷尽了风控面。
5. **现成社区工具对"环境一致性"覆盖与 iso-cc 高度重叠但对"保证域"覆盖为零**（与 canary 研究结论一致）：check-cc 40+ 维度 ≈ P6/P7/R12-P2~P4 的 web 版；claude-ip-guard ≈ P1+区域检查的 cc-hook 形态；没有任何工具做 egress 钉死对照、写集、宿主零残留、OAuth 回环闭合、**会话内出口恒定**。
6. **T5/R12 增补建议（全部小成本）**：P13 出口归属地 ∈ 官方支持列表（硬断言，唯一官方语义）；P14 IP 类型/欺诈分情报（WARN 留档不断言——存活反例太多，硬断言会误杀合法 egress）；P15 会话生命周期内出口 IP 恒定（回应社区最高频的"IP 漂移"信号）；R12-P9 补"OAuth 授权时刻出口未漂移"断言；fc-list zh 字体仅 WARN 记录；verify 增加"不覆盖面"声明。**不采纳**：使用时段/用量/内容类"探针"（无环境语义）。

## 三、T5/R12 增补建议

映射依据：社区信号 → 是否环境可测 → 是否与 iso-cc 保证域绑定。**原则**：只有"会话环境与声明一致"类断言进矩阵；账号/行为/内容层一律进"不覆盖面"声明，不做伪装承诺（与 R12"同域+稳定，不是反取证"一致）。

### 3.1 建议新增探针

| 建议 | 内容 | 断言/级别 | 社区依据 | 成本 |
|---|---|---|---|---|
| **P13 出口归属地 ∈ 官方支持列表** | P1 同一端点的 geo 字段（ip-api `country`/`countryCode`）对照 anthropic.com/supported-countries 快照（快照+日期存档，清单会变） | **FAIL 级硬断言**：归属地不在列表 → verify 判 1（环境不合格）。这是唯一有官方语义（确定性 400）的风控面，环境工具完全可测 | GH#2656 [一手]；社区"中国 IP 只报不支持" | 低（一次 geo 查询 + 静态清单） |
| **P14 IP 类型/欺诈分情报** | ip-api `proxy`/`hosting` 字段（或 scamalytics/ipinfo 留档）；检出机房/代理标记 | **WARN 级留档，不 FAIL**：社区共识面但存活反例密集（IDC 稳用/家宽照样封），硬断言会误杀大量合法 egress；egress 是用户声明值，工具只报告风险不裁决 | NodeSeek post-949485、V2EX t/1207240 [多例] | 低 |
| **P15 会话内出口恒定** | verify 开始/结束各采样一次 P1（及 P3 解析器），断言两值相同；发现中途漂移即 FAIL | **FAIL 级**：iso-cc 的 egress 钉死本应保证恒定；"IP 漂移/瞬移"是社区最高频信号（A4），"会话内漂移"是其唯一可测切片（跨会话历史频率出界） | A4 [社区-共识趋势] | 低（复用 P1 两次） |
| **R12-P9 补断言：OAuth 授权时刻出口未漂移** | P9 流程中 `/login` 前后各采样浏览器出口（探针页）与 cc 出口，断言与 egress 一致且未变化 | FAIL 级；回应 C1"授权 IP 与使用 IP 分叉"信号 | C1 [社区-共识] | 低 |
| **P6 扩展 WARN：zh locale 资产存在性** | `fc-list :lang=zh` 非空、`locale -a` 含 `zh_*` 时 verify 报告 WARN（不 FAIL） | WARN 级；证据仅孤例传闻（B3），且宿主 HOME 共享场景可能无法避免，设 FAIL 不合理 | B3 [社区-孤例传闻] | 极低 |

### 3.2 建议的"不覆盖面"声明（verify 输出固定附注）

verify 报告应固定输出一节，声明以下社区共识信号**结构性不可由环境工具覆盖**，防止"探针全绿=账号安全"的误读（TL;DR-3 的反证链）：

1. 行为/用量模式（D1/D5）、对话内容与项目特征扫描（D2）、使用时段（D3，本身即迷信）；
2. 账号层：账号年龄（D4）、支付方式与卡头连坐（E1–E3）、邮箱来源（E4）、KYC/手机验证（E5/E6）、申诉通道（E7）；
3. 历史维度：IP 切换历史/与被封设备的关联（A3/A4 跨会话部分/C2 的设备库关联）——环境探针只能断言"当前会话"，无法断言"历史画像"；
4. 反取证伪装（C3/VanishMe 类）属非目标：iso-cc 承诺"同域+稳定+与声明一致"，不承诺"不可识别"。

### 3.3 明确不采纳

- 时段/用量/内容类任何"探针"（无环境语义，且 D3 已降级为迷信）；
- 把 P14 欺诈分设为 FAIL（存活反例密集，见 TL;DR-3）；
- VM 特征探针（B5）：iso-cc 会话与宿主共享内核，本就等同用户日常开发机，无特征面可测；
- 反取证伪装探针（非目标条款）。
